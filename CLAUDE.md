# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**South 1.0.0** is a Colorlib **WordPress block theme** (Full Site Editing) for
real-estate agencies, plus a companion plugin, **South Listings 1.0.0**, in
`plugin/south-listings/`. 33 patterns, 15 templates, 3 parts, 8 colour
palettes × 5 typography presets, visitor dark mode, text domains `south` and
`south-listings`. It is **not** a static HTML template: the Colorlib R2
preview/download flow and the HTML-template upgrade phases in the global
instructions do not apply.

It was built from the **South 3.0.0 HTML template**
(`~/Fresh Projects/colorlib-premium-upgrade/templates/south`, commit 51a0a8a,
preview.colorlib.com/theme/south/), and it is meant to match it: hero height,
the uppercase title on the black band, the search box overlapping the hero,
the card anatomy, section rhythm, header and footer. **Fidelity is the bar**:
the owner has rejected quieter "relatives" of a design before. The measured
side-by-side comparison is `.dev/FIDELITY.md`; rerun `.dev/fidelity.mjs`
after any visual change.

Distribution is **self-hosted** (`Update URI` → updates.colorlib.com, filter
`south_check_for_updates`, which the plugin honours too). Not WordPress.org.
Requires WP 6.6+, PHP 7.4+. No npm build: every file is committed as-is.

`node --check` every JS file, `python3 -m json.tool` every JSON file.

### How listings reach blocks

- The **card** is a `core/query` loop of ordinary blocks. Its tag, price,
  address and facts are paragraphs bound to the plugin's **`south/property`
  bindings source**, which returns formatted values ("$2 450 000", "For Rent",
  "4,200 sq ft"). Every field is also registered with `show_in_rest` and an
  **unprotected key** (`south_price`, not `_south_price`), so `core/post-meta`
  bindings work too.
- Featured grids ask for featured homes with `"southFeatured":true` in the
  query object, read by `query_loop_block_query_vars`. The EDITOR preview
  ignores it (it queries over REST) and shows the newest homes instead.
- The archive's loop has `inherit: true`; the plugin applies the search to the
  MAIN query in `pre_get_posts` from plain GET parameters (`city`, `type`,
  `status`, `beds`, `sort` …, the HTML template's names), so the toolbar, the
  loop and core's pagination agree with or without JavaScript.

### Rules that cost real debugging (here or in earlier themes)

- **The theme owns the entry points; the plugin plugs in through
  `south_listings_render`.** Never declare one function in both:
  Academia did, and activating its plugin with the theme active fataled
  ("Cannot redeclare"). `.dev/no-shared-functions.sh` checks it statically;
  `.dev/activation-check.mjs` checks it live. The theme's helpers are
  `south_*` but never `south_listings_*`, which is the plugin's prefix.
- **Dynamic sections are never PHP inside a pattern** (frozen once expanded
  into a page). They are query loops with bindings, or shortcodes.
- **`core/shortcode` wpautop()s its output**, nesting a `<div>` or `<form>` in
  `<p>`. `south_render_shortcode_block()` renders the block's raw inner HTML.
- **Sections that need the plugin carry `south-requires-listings`** and are
  removed without it; `south-without-listings` marks their stand-ins.
- **Alignfull sections get `margin-top/bottom: 0`, never `margin: 0`**, which
  cancels the negative inline margins that make them full width.
- **Core's navigation link rule is (0,4,0).** Style links with
  `.wp-block-navigation.south-nav .wp-block-navigation-item__content.wp-block-navigation-item__content`.
- **The editor gives every block `position: relative` at (0,2,0)**, so
  absolutely positioned pieces (card tag, price) need three classes.
- **Insert pattern content with `wp_slash()`**; claim the setup flag only after
  something was created, with an `admin_init` retry (Pato, Unioncorp).
- **Any colour on a non-`base` ground has its own slug** (`on-dark`,
  `on-primary`, `overlay`); dark mode lifts `primary` and `primary-text` from
  `accent` (audited); the dark button is `contrast` on `base`, not black.
- **Validate stored pages and menus**, not just patterns, on a FRESH
  Playground after a pattern change (pages are copies made at activation).
- **Playwright's `framenavigated` fires on pushState.** To prove "no page
  load", set a marker on `window` and check it survives.

## Theme Check

Run it on the BUILT theme (`sh .dev/build-zip.sh && sh .dev/theme-check.sh`).
Exactly these REQUIRED findings are expected and intended:

| Finding | Why it stands |
| --- | --- |
| `Update URI` in style.css | Required by self-hosted distribution. |
| `add_shortcode()` in `inc/enquiry.php` and `inc/listings.php` | The only mechanism that survives a pattern being expanded into post content, and the theme's listing entry points. |
| Reference to unsplash.com | The template's photographs, credited in readme.txt; the Unsplash License is not GPL. |

## Release checklist

1. Lint PHP, JS, JSON; `python3 .dev/dead-selectors.py`; `sh .dev/no-shared-functions.sh`.
2. Regenerate what changed; normalize then validate on a fresh Playground.
3. Rendered checks: contrast (`SOUTH_PALETTES=all`), buttons, overflow, alignment, search, activation, editor shots.
4. `.dev/fidelity.mjs` against the HTML template; update `.dev/FIDELITY.md`.
5. Bump `Version` (style.css, `SOUTH_VERSION`, readme `Stable tag`) and the plugin's header + constant.
6. `sh .dev/build-zip.sh`, Theme Check, then install both zips on a fresh Playground.
7. Do NOT push, upload to R2, or touch updates.colorlib.com without the owner.
